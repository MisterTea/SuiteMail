# Workflow 24 — Manual filter → preview → apply and sync

## Evidence

- Reviewed `recordings/android/workflow-manual-filter-creation-transitions-to-same-accept-reject-pane-with-retroactive-filtering-preview-and-sync.png`. Its final Settings frame retains a wide navigation column, compressing Mail Rules into approximately half the screen: “Manual Tech Filter” wraps across three lines; “+ Add filter” wraps across two. This frame demonstrates the saved result, not the open form or keyboard.
- `FilterEditor.tsx` routes Add filter into `AiFilterSuggestModal` with `initialMode="manual"`. The modal currently uses an inset, 88vh dialog; a crowded header; 11–12px condition labels; unassociated text labels; small checkbox rows; and a horizontal footer containing explanatory text and two actions.
- `handleManualPreview` builds criteria/actions and enters the shared review pane before the async preview completes. Review currently displays an empty-match message while loading; Add Filter is guarded by saving only. Preview requests are limited to 50, but copy promises “whole inbox.” Save inserts the rule, applies the preview thread IDs when checked, then starts sidecar upload without awaiting it. These are code findings; the supplied still does not establish keyboard, loading, failure, or sync behavior.

## Three mobile improvements

1. **Give the manual form the screen and semantic labels.** Below 640px, use a full-width, viewport-height dialog with 16px content padding, a simple title/close header, and the mode switcher on its own row. Use 16px input text, 14px visible labels, 48px minimum field and button height, and full-width stacked fields. Associate every text input/select with a persistent label using `htmlFor`/`id`; label the close button “Close filter editor.” Give Mail Rules a full-width mobile Settings detail view so the saved rule remains readable.
   - Acceptance: at 360px and 390px widths, no horizontal page/dialog scrolling; long names wrap without colliding with actions; all inputs announce their visible label in TalkBack; mode tabs and close have at least 48×48px hit areas. At 200% text size, content remains available through vertical scrolling.

2. **Disclose conditions and actions progressively.** Show “Match all conditions” with From initially visible; place To, Subject, Body, and Has attachment inside an accessible “More conditions” disclosure. Keep Actions visible with a stacked folder selector; reveal the new-folder field only after choosing “Create new folder.” Put Archive, Star, Mark as read, and Move to Trash in separate 48px tappable checkbox rows. Preserve all values when collapsing sections and returning from review, and summarize selected hidden conditions in the disclosure label.
   - Acceptance: expanding/collapsing changes `aria-expanded`; checking a row toggles it once; no selected condition disappears from the review summary. Existing folder and new-folder choices are mutually exclusive and review displays the folder name rather than its internal ID. A first-time user can enter sender + archive and reach preview without opening advanced conditions.

3. **Keep preview, errors, and apply reachable above the keyboard.** Use one scrollable form body and a nonshrinking mobile footer with full-width “Preview & Continue,” followed by Cancel; use the same structure for “Add filter” and Discard in review. Size against the visible viewport, include bottom safe-area padding, and scroll the focused field/error into view. Announce validation with `role="alert"`, link errors to fields, and retain edits after errors. During preview show “Calculating matching emails…” and disable Add until preview succeeds; offer Retry on failure. Put retroactive scope next to the apply decision, accurately distinguishing displayed preview from total affected messages; communicate saved versus syncing state separately.
   - Acceptance: on Android with the keyboard open in the final field, the field, its error, and primary action remain reachable without dismissing the keyboard. Empty/invalid submissions announce an actionable error and keep entered values. Preview failure never shows “No existing emails match” or enables Add. Double tapping Add creates one rule. Checked retroactive scope updates the promised matching messages; unchecked scope changes no existing messages. Sync failure does not falsely announce synced success or create a duplicate rule when retried.
