# Storyboard 04 — Reply all

## Observed evidence

- `recordings/android/storyboard-4-reply-all.png` (1080 × 2400) shows the thread after interaction with a software keyboard still occupying the lower screen. The reply editor and Send are not visible. Reply and Reply all appear as neighboring unlabeled arrows; Reply all has a green `4` badge. Visible message metadata names Sarah and two To addresses, including the signed-in-looking `user@test.com`. The image does **not** establish the outgoing recipient list or delivery success; the badge cannot be trusted as proof of four actual reply recipients.
- `email/ActionBar.tsx` supplies 48px touch targets and accessible labels, but renders icon-only reply controls and swaps their positions with `defaultReplyMode`. Its badge counts raw From/Reply-To, To and Cc strings without excluding the active identity or normalizing equivalent addresses.
- `composer/Composer.tsx` names Reply All and offers a recipient disclosure. The sender-only switch is `hidden sm:inline`, making it unavailable on phones. A collapsed horizontally scrolling summary can conceal Cc. Full Cc/Bcc editing depends on `showCcBcc`; populated fields should remain discoverable regardless of this toggle. Mobile height uses `100dvh`; the editor scrolls and Send has a 48px target, but the image demonstrates that keyboard return behavior still needs device verification.
- `composer/AddressInput.tsx` truncates recipient chips, provides 28px remove targets, and commits input on blur by calling `addAddress`, which focuses the field again. This can reopen or trap the keyboard. Tab is always prevented, even when the input is empty, interrupting external-keyboard traversal. Address deduplication compares raw strings.

## Three exact mobile touch changes

1. **Make reply scope explicit before typing.** In `ActionBar.tsx`, show labeled **Reply** and **Reply all** controls in a stable order within a wrapping mobile reply row, with 48px minimum height. Move ancillary actions to the existing overflow if needed. Preserve the user's preferred primary emphasis without swapping positions. In the composer, retain **Reply all · N recipients**, expose a 48px **Reply to sender** mode control on mobile, and preserve body, attachments and thread identifiers when changing scope. Compute the badge from the same normalized outgoing recipients as the composer: honor Reply-To, deduplicate mailbox identities across To/Cc, exclude the sending account and known aliases, preserve To/Cc roles, and never infer Bcc recipients from thread history. Sender-only switching must use the original sender/Reply-To, not the first recipient after user edits; announce changed scope.
2. **Make the audience reviewable and editing deliberate.** In `Composer.tsx`, show separate wrapping **To · N** and **Cc · N** summaries whenever populated, plus a 48px **Review recipients** disclosure; show populated Bcc distinctly when explicitly added by this author. Expand to labeled fields with full-address inspection available by tapping a chip; long addresses wrap in the inspection view. Never rely on hover titles or horizontal scrolling to reveal an audience. In `AddressInput.tsx`, give each removal action a nonoverlapping 48px target and an accessible full-address label. Normalize and validate pending input before Send; invalid text stays visible with an inline field error, blocks sending and receives focus. Distinguish recipient counts from message counts. No extra confirmation is required for every normal send.
3. **Keep recipient editing and Send reachable with the keyboard.** In `AddressInput.tsx`, separate commit from refocus: selecting a suggestion or pressing Enter may keep focus, but blur must not call a path that re-focuses. Allow empty-field Tab to advance; expose suggestions with combobox/listbox semantics and retain explicit dismissal. In `Composer.tsx`, use the shared keyboard-adjusted viewport, a scrollable recipient/editor region and a non-shrinking Send footer. Hide thread bottom navigation while composing, keep the active input/caret visible after viewport resize, and explicitly blur on successful send queueing or close. Do not dismiss the keyboard on a validation error. Keep the scope label and recipient review reachable without forcing a journey back to the thread.

## Acceptance criteria

- At 320, 360 and 412 CSS px, Reply and Reply all are text-labeled, reachable without horizontal scrolling and stable in order; all new tap actions have at least 48px targets. TalkBack announces scope and actual recipient count.
- With Sarah sending to the current account and Alex and Cc'ing Priya, Reply all contains Sarah/Alex in To and Priya in Cc, excludes the current identity and aliases, and counts three unique outgoing recipients. Mixed-case and display-name variants do not duplicate a mailbox. Reply-To overrides From appropriately. Original hidden Bcc recipients are never invented.
- Before Send, every populated audience group is visible and expandable; tapping a long recipient exposes the full address. Removing or editing one recipient changes only that recipient. Switching to sender-only retains the draft and selects the original sender/Reply-To even after To was reordered.
- With Android keyboard open in portrait and landscape, a long recipient list, autocomplete and a long body remain scrollable while Send is visible and tappable. One tap queues once. Pending invalid address input cannot be silently dropped or sent; correcting it clears the error.
- Tapping from a partially entered address into the body commits a valid address without pulling focus back. External-keyboard Tab progresses through fields and controls. Android Back dismisses the keyboard without losing the draft; successful send/close leaves the keyboard dismissed on the thread, matching the provided end state with the keyboard absent.
