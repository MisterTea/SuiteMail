# Storyboard 01 — Read and browse inbox

Scope: phone inbox → open conversation → read → return to the same inbox position. Design specification only; shared implementation is coordinated separately.

## Evidence and observed problems

- `recordings/android/storyboard-1-read-browse-inbox.mp4`, 3.5 s: sender, full date, pin, star and multiple unread indicators compete on every row. The date plus two quick actions consume much of the sender line. `ThreadCard.tsx:423–536` puts these in one flex row; `:414`, `:436`, and `:355` repeat unread emphasis with an avatar dot, another dot and left border. Pin state is also repeated (`:464`, `:582`).
- Final `storyboard-1-read-browse-inbox.png`: the sender becomes “Super...” while a long timestamp remains fully visible; sender address appears twice. `MessageItem.tsx:161–204` uses a nonshrinking `formatFullDate` chip beside a truncating sender and renders the address inline plus again below on mobile.
- Final image: the reading toolbar shows Back, Folders, Reply, Reply All, Forward, Archive and Delete; more actions require undisclosed horizontal scrolling. `ActionBar.tsx:325` hides the horizontal scrollbar. Existing 48 px mobile action targets are a good baseline, but labels still include desktop keys (`:417`, `:431`, `:530`).
- Final image: seven bottom destinations compete for a 360 px logical-width phone, including a large Compose control. `MobileNavBar.tsx:16–134` distributes seven controls without explicit 48 px minimum target widths or bottom safe-area padding. `MailLayout.tsx:43` reserves a fixed `pb-14`, which must stay aligned with the actual navigation height.
- Inbox rows use a parent button containing checkbox-like and button-like descendants (`ThreadCard.tsx:340–384`, `:490–536`). The avatar selection area is only 28–40 px depending on density. Swipe handling records only X (`:200–263`), so vertical reading gestures can cause horizontal drift or accidental action.

## Exact proposed changes

1. **Make sender and subject dominant.** On mobile, use 16 px horizontal row padding, 12 px vertical padding, 16 px sender/subject text and a 14 px one-line preview. Put a short date (`Today`, weekday, or `Nov 14`) at the trailing edge; retain the complete date for accessible text/details. Keep one unread dot plus semibold sender/subject; remove duplicate unread dots/glow. Keep Star as a 48 × 48 px trailing control; represent existing Pin as one small status icon and put Pin/Unpin in the row actions menu. Do not reserve an empty pin button on every row. Allow a two-line subject at narrow widths when required. Keep rows at least 88 px tall in the default phone density.
2. **Reflow message identity instead of truncating it behind metadata.** Sender gets the first line; a short date and collapse chevron sit alongside with bounded width. Put `to me · Details` on the next line. A 48 px Details target opens sender address, To/Cc and full timestamp as selectable wrapping text. Remove the mobile duplicate address and timestamp pill decoration. Give header toggle the accessible name `Collapse message from {sender}` / `Expand message from {sender}` and preserve `aria-expanded`. Body text stays at least 16 px with 1.5 line height; translation becomes a secondary 48 px action in message details or overflow, leaving the body near the header.
3. **Provide an explicit reading action hierarchy.** Mobile top bar: Back to inbox, Archive, Delete, More; every target 48 × 48 px, no horizontal scrolling. More opens a labeled bottom sheet for Mark unread, Star, Snooze, Move, Pin and other applicable actions. Put Reply plus a reply-options affordance in the bottom reachable reading area; Reply All and Forward remain labeled sheet choices. Keep existing desktop toolbar at desktop breakpoints. Mobile accessible labels contain action words without shortcut suffixes. Preserve inbox filter and scroll position on Back and Android system Back; move focus to the originating row.
4. **Simplify mobile global navigation.** Coordinate with the shared navigation owner: Inbox, Starred, Compose, More, with Folders/Calendar/Tasks/Settings available in More. Use 48 px minimum target width/height, text labels, `aria-current` for active destination and `env(safe-area-inset-bottom)`. Set one shared navigation-height variable for fixed navigation and layout/content padding. A reading action footer, if fixed, sits above this reserved area and does not obscure content.
5. **Separate selection and opening semantics.** Render each row as a noninteractive container with distinct open-conversation button and sibling Star/Select controls; all controls expose meaningful labels including sender/subject. Avatar selection target is 48 × 48 px at every phone density. On touch, lock horizontal swipe only after horizontal displacement exceeds 12 px and is at least 1.5× vertical displacement; cancel on vertical scroll or `touchcancel`. Keep swipe as optional acceleration: visible menus perform the same actions and destructive swipes retain Undo.

## Acceptance criteria

- At 320, 360 and 412 CSS px wide, sender/subject remain legible; no toolbar or page horizontal scroll is needed. At 200% font scale, sender, metadata and menus wrap without covering other controls.
- A user can open a row, read, expand message details, mark unread and return using touch alone. Back and Android Back restore the same folder, filter and scroll offset; focus returns to the row.
- All actionable phone controls have nonoverlapping 48 × 48 px hit areas. Bottom controls clear gesture/navigation insets; the final line of any message can scroll fully above fixed controls.
- TalkBack identifies row open, Select, Star, Back, message expansion and More independently; selected, unread and current-navigation state are announced. Shortcut characters are not spoken in mobile action names.
- Vertical swipes starting on a row never archive/delete; horizontal gestures never unexpectedly open a message. Swipe cancellation restores the resting row. Every swipe action has an equivalent labeled tap action.
- Verify read/unread row styling, long sender/subject/address, multi-message thread, long body, attachment and loading states. Preserve existing desktop layout and keyboard behavior.

Evidence limitation: the recording shows loading, inbox and one opened message, and does not demonstrate return-position restoration, large text, TalkBack or gesture failure; these are verification requirements, not claimed observed failures.
