# Storyboard 05 — Forward Email

## Evidence reviewed

- `recordings/android/storyboard-5-forward-email.png` (1080 × 2400) shows the original thread: the top Forward action is an unlabeled arrow beside Reply and Reply All; a labeled Forward button appears farther down beneath the message. The original sender is truncated beside a long timestamp.
- The 9.06-second MP4 sampled at 5 seconds shows that same thread; at 7 seconds it shows “Forward Email,” a committed `manager@workplace.org` recipient, the forwarded subject, a large preservation banner, formatting controls, and Send directly above the Android keyboard. This establishes reachable Send in that state, but does not establish the initial empty-recipient state, attachment preservation, or delivery.
- `email/ActionBar.tsx` makes Forward icon-only with a 48px mobile target in a horizontally scrolling toolbar. `composer/Composer.tsx` already labels the mode “Forward Email,” autofocuses the forward recipient field, and disables Send when `to.length === 0`. It automatically expands forwarded quote details, displays a separate preservation banner, and has 48px Send/schedule targets. `getOutgoingHtml` includes quoted content independently of disclosure visibility.
- `composer/AddressInput.tsx` provides an email keyboard, 16px mobile text, and the “Forward to” empty state; the input has a 44px minimum height and commits typed text on blur. The Send button depends on committed recipients, so a typed but uncommitted address needs explicit verification.

## Three exact small-screen changes

1. **Make Forward explicit and start with an empty destination.** In `ActionBar.tsx`, render arrow + visible **Forward** below the mobile breakpoint, with a minimum 48px height and accessible name “Forward”; keep it reachable without horizontal scrolling. Preserve the composer title. Open forward with To/Cc/Bcc empty, expand To, focus its 48px email input, and use **Forward to** as its accessible label. Keep “Enter recipient to forward to…” guidance until a destination is committed. Do not inherit the original sender or recipients. Invalid addresses must show an inline explanation rather than becoming valid-looking chips; Send remains disabled until a valid destination exists.
2. **Collapse forwarded content into one truthful summary.** In `Composer.tsx`, initialize forward quote details collapsed on small screens. Replace the tall mobile preservation banner with a compact disclosure, **Original message · N attachments**, above or directly after the authored message area. Its 48px control exposes `aria-expanded` and `aria-controls`; opening it shows sanitized sender/date/subject/body and the actual attached filenames. Derive the count from outgoing attachments, show zero accurately, and avoid claiming attachments are preserved before they are loaded. Expanding/collapsing must not edit the draft or alter outgoing quote/attachment inclusion. Keep quote removal separate and explicitly named **Remove original message**.
3. **Keep Send stable while typing.** Preserve the existing 48px Send target and keyboard-visible footer; allow secondary footer controls to wrap or move into an overflow control at 320px. Let the message editor scroll inside the keyboard-adjusted viewport, with a short mobile placeholder “Add a message…”. Commit a valid typed recipient on the keyboard’s Done action so Send becomes available without an extra tap elsewhere. On successful queue creation, dismiss keyboard focus, close the composer, and announce “Sending — Undo available”; announce “Sent” only after delivery succeeds. Validation failure retains focus and text; delivery failure retains a recoverable draft and presents Retry.

## Acceptance criteria

- At 320, 360, and 412 CSS px, Forward is visibly labeled and reachable without sideways scrolling; recipient, disclosure, close, and Send controls meet 48px touch sizing and show keyboard focus.
- Opening Forward starts with empty To/Cc/Bcc, focuses the email input, and cannot send to the original recipients accidentally. Entering a valid address then Done enables Send; an invalid or empty destination cannot send and receives readable guidance.
- With the Android keyboard open in portrait and landscape, Send and the active caret remain visible through long typing, recipient entry, and quote expansion. Global bottom navigation never covers the composer.
- Quote details start collapsed on mobile. Disclosure preserves authored text, quote contents, and attachments; the displayed count and filenames match the actual outgoing payload. A no-attachment forward never implies that files were included.
- One Send tap queues once. Keyboard closes after queueing; Undo, actual success, and failure are announced accurately. Verify a forward with an attachment and one without on the Android WebView; the existing recording alone cannot validate either payload.
